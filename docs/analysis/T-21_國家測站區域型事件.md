# T-21 分析紀錄：國家測站的區域型事件候選

**日期：** 2026-10-19

## 完成了什麼

- `src/analytics/regional.py`：在國家測站上計算「升高」、一致性 C、站間變異係數 CV；找區域型候選日、區域型時段（連續 6 小時以上）、局部型候選小時
- `tests/test_regional.py`：4 個合成資料測試（全部測試 17 個通過）
- `notebooks/T-21_regional_events.ipynb`（由 `notebooks/make_t21_notebook.py` 產生）與圖 `t21_fig1～3_*.png`

## 方法

| 項目 | 規則 |
|---|---|
| 升高 | 比自己之前的中位數高 50% 以上，**且**至少高 5 μg/m³（日尺度：前 14 天日平均；時尺度：前 7 天小時值；都不含當下） |
| 區域型候選 | 升高的測站比例 C ≥ 0.8，且站間變異係數 CV ≤ 0.25 |
| 區域型時段 | 上面的條件在小時尺度連續 6 小時以上 |
| 局部型候選 | 單一測站比其他測站中位數高 max(10, 50%) 以上，且 C < 0.3 |

C ≥ 0.8 比微型感測器的 0.6 嚴格，因為臺中只有 6 站，一站就佔 17%。

## 結果（2026-08-20～10-19，臺中 6 站、高雄 12 站）

**區域型候選日：**

| 城市 | 候選日 | 最明顯的一天 |
|---|---|---|
| 臺中 | 9/08、9/09、9/13、10/12、10/13、10/14、10/17（7 天） | 10/13：6 站全部升高，日平均 22.9～30.9 μg/m³，CV 0.11，約為前 14 天基準的 2.2 倍 |
| 高雄 | 9/09～9/12（4 天，連續） | 9/11：12 站全部升高，日平均 19.0～28.0，CV 0.10，約為基準的 3.1 倍 |

**區域型時段（小時尺度）：**臺中 5 段（最長 10/13 17 時～10/14 05 時，13 小時，城市中位數最高 38.5）、高雄 2 段（最長 9/12 01～10 時，10 小時，最高 34.0）。

**局部型候選：**臺中 56 個小時、高雄 179 個小時；高雄集中在小港（39）、大寮（34）、林園（28）。最明顯的是高雄小港 9/27 19 時 55 μg/m³（其他站中位數 7）、臺中大里 10/04 21 時 50 μg/m³（其他站中位數 15）。這些多半只持續 1～2 小時。

**兩市同時為候選日：**只有 9/09。兩市日平均的相關係數 0.74。

## 方法修正（實測後）

- 只用相對門檻 +50% 時，8 月底城市平均只有約 8 μg/m³ 的日子也被選出來（基準約 4，升高約 4）。加上絕對門檻 +5 μg/m³（與 Algorithm 2 的 `regional_excess_abs` 相同）後排除。

## 限制（誠實列出）

1. **成因無法判斷：**多站同時升高只代表空間型態一致，可能是天氣型態（擴散差）或區域／境外傳輸，需要對照環境部空品預報或境外污染預警紀錄（待查證，尚未找到可引用的當日紀錄）。
2. **緩慢的季節性上升不會被選出：**高雄 10/13～10/17 日平均都在 20 以上，但前 14 天基準也逐日上升，所以 C 不夠高。這是刻意的（事件 ≠ 季節變化），但持續數週的高污染期需要另外用絕對濃度描述。
3. **國家測站很稀疏：**測站尺度的「區域型」是城市尺度（數十公里），比 Algorithm 2 的 15 km 大；要驗證 Algorithm 2 本身，仍需要同一時段的微型感測器資料。微型感測器 API 只保留約 4～5 小時，**這些 9～10 月的候選日無法回補微型感測器資料**，只能等之後排程收集到的新事件。
4. 局部型候選小時很多是單一小時的跳動，可能是測站附近的短暫排放，也可能是儀器雜訊，測站資料本身無法分辨。

## 對設計的影響

- 區域型規則在**測站尺度**上有真實的候選事件可以對照：期末收集到新的區域型日子時，可以同時看測站 C 與微型感測器 C，校準 Algorithm 2 的 0.6。
- 建議在 Algorithm 2 的「升高」也加入絕對門檻（目前只有 `rise_ratio`）。**尚未修改 `spatial.py`**，等微型感測器多天資料（`claude/T-20-multiscale` 分支）一起驗證。
